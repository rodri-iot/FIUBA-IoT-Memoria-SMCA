Este capítulo presenta los principales componentes tecnológicos que conforman el sistema de monitoreo de caldiad de aire (SMCA) desarrollado. Se describe la arquitectura general, los dispositivos seleccionados y las tecnologías de comunicación utilizadas. También se exponen los escenarios de uso previstos y las posibles aplicaciones prácticas de la solución.

\section{Arquitectura general del sistema}
\label{sec:Arquitectura general del sistema}

El sistema se organiza en torno a tres componentes principales: nodos sensores distribuidos, mecanismos de transmisión y una plataforma web de consulta. Esta estructura permite recolectar datos ambientales para su posterior procesamiento en una infraestructura centralizada. La figura \ref{fig:2-1-diagrama} ilustra de forma esquemática la interconexión entre estos elementos.

\begin{figure}[h]
    \centering
    \includegraphics[width=1\linewidth]{Figures/2_1-diagrama.png}
    \caption{Diagrama de bloques del sistema de monitoreo de calidad de aire.}
    \label{fig:2-1-diagrama}
\end{figure}

Cada unidad recolectora utiliza el microcontrolador ESP32 Heltec V3 \cite{heltec:v3} para la gestión de sensores y la comunicación inalámbrica. El nodo integra sensores específicos para medir material particulado, gases contaminantes y variables climáticas.

La transmisión de datos se realiza hacia un servidor central mediante el protocolo MQTT (del inglés, \textit{Message Queuing Telemetry Transport}) sobre una red Wi-Fi. Finalmente, una plataforma web desarrollada con herramientas modernas permite la visualización de la información en tiempo real.

Se seleccionaron sensores ambientales con un equilibrio entre costo y confiabilidad técnica. Estos componentes permiten caracterizar la calidad del aire mediante la medición de partículas y gases. Los sensores principales que integran la solución se muestran en la figura \ref{fig:2-3-sensores}:

\section{Tecnologías de comunicación utilizadas}

El sistema emplea una red Wi-Fi para la transmisión de datos desde los nodos sensores hacia el servidor central. Esta tecnología permite el despliegue de los dispositivos en entornos con infraestructura de red preexistente. El esquema de comunicación se basa en el protocolo MQTT con una capa de seguridad adicional.

MQTT se caracteriza por su bajo consumo de ancho de banda y su eficiencia en redes inalámbricas. El protocolo utiliza un modelo de publicación y suscripción que facilita la gestión de múltiples nodos de forma simultánea. Esta arquitectura resulta adecuada para aplicaciones de monitoreo ambiental donde se requiere un flujo de datos constante y ligero.

La seguridad en la transmisión se garantiza mediante el uso de certificados TLS. Este mecanismo asegura la autenticación de los nodos emisores y la confidencialidad de la información. La integración de TLS protege el sistema frente a posibles ataques de interceptación en la red. La figura \ref{fig:2-4-mqtt} muestra el diagrama del protocolo MQTT con TLS.

\section{Plataforma web para visualización}

El sistema cuenta con una aplicación web diseñada para asegurar una experiencia fluida en diversos dispositivos. Se seleccionó la biblioteca React \cite{react_web} para el desarrollo del frontend. La arquitectura se basa en el modelo de \textit{Single Page Application} (del inglés, aplicación de una sola página). El entorno de desarrollo y construcción del proyecto utiliza Vite \cite{vite_web}.

La navegación entre las diferentes vistas del sistema se gestiona mediante la biblioteca \texttt{React Router}. Para el diseño visual y la disposición de los elementos se emplea \texttt{Materialize CSS} \cite{materialize_css}. Esta herramienta permite aplicar estilos consistentes y asegurar la adaptabilidad de la interfaz a pantallas de distintos tamaños.

Para la visualización de datos en tiempo real, se implementa la tecnología de \textit{Server-Sent Events} (SSE). Este mecanismo permite que el servidor envíe actualizaciones automáticas al navegador cuando se registra una nueva medición. La representación gráfica de los contaminantes se realiza con \texttt{Recharts}. El manejo de fechas y zonas horarias se delega en \texttt{Luxon}.

\section{Infraestructura del servidor y persistencia}

El backend del sistema se desarrolla sobre el entorno de ejecución Node.js \cite{nodejs_web}. Se utiliza el marco de trabajo Express \cite{express_web} para la creación de los servicios y la gestión de las rutas. La seguridad en el acceso se implementa mediante \texttt{JSON Web Token} (JWT) para la autenticación y \texttt{bcrypt} para el cifrado de contraseñas.

La persistencia de la información se realiza en una base de datos no estructurada MongoDB \cite{mongodb_web}. Para la interacción entre el servidor y la base de datos se emplea \texttt{Mongoose}. Esta biblioteca actúa como un mapeador de objetos y documentos para definir esquemas y realizar consultas eficientes. El sistema se apoya en \texttt{dotenv} para la configuración de variables de entorno.

Todo el entorno de ejecución se empaqueta mediante contenedores Docker \cite{docker_web}. El despliegue y la orquestación de los servicios se coordinan a través de \texttt{Docker Compose}. Esta metodología garantiza la paridad entre los entornos de desarrollo y producción, simplificando la instalación de dependencias y la configuración de la red interna.

\section{Infraestructura de despliegue y servicios en la nube}

En esta sección se describen las tecnologías de infraestructura y servicios en la nube que integran el sistema. Estas herramientas optimizan la disponibilidad, la seguridad y el escalamiento de la solución frente a la demanda de datos.

\subsection{Amazon Elastic Compute Cloud (EC2)}

Amazon EC2 \cite{aws_ec2} es un servicio de computación que ofrece capacidad informática escalable bajo demanda. Esta tecnología permite el control total sobre el sistema operativo Ubuntu para la ejecución del servidor central. La plataforma facilita el ajuste de recursos según el flujo de datos de los sensores y reduce los costos de mantenimiento de hardware físico.

\subsection{Amazon Simple Storage Service (S3)}

Amazon S3 \cite{aws_s3} proporciona un almacenamiento de objetos escalable y de alta durabilidad. Esta tecnología resulta ideal para alojar los archivos estáticos de la aplicación web de forma segura. El servicio garantiza una alta disponibilidad de la interfaz de usuario y permite una gestión eficiente de grandes volúmenes de datos mediante una infraestructura global.

\subsection{Amazon CloudFront}

Amazon CloudFront \cite{aws_cloudfront} actúa como una red de entrega de contenidos que distribuye los datos con baja latencia. Esta herramienta acelera la carga de la plataforma web al servir el contenido desde ubicaciones geográficas cercanas al usuario. El servicio integra mecanismos de seguridad para proteger la aplicación frente a ataques de red y asegura una experiencia de navegación fluida.

\subsection{Caddy y Let's Encrypt}

Caddy \cite{caddy_server} se emplea como servidor de proxy reverso para gestionar el tráfico hacia el backend de forma segura. La principal ventaja de esta tecnología es la automatización del protocolo TLS mediante Let's Encrypt \cite{letsencrypt_org}. Este proceso elimina la configuración manual de certificados digitales y garantiza que todas las comunicaciones entre los clientes y el servidor utilicen cifrado de grado industrial.

\subsection{MongoDB Atlas}

MongoDB Atlas es un servicio de base de datos en la nube que simplifica la administración de clústeres de datos. Esta plataforma ofrece ventajas en términos de escalabilidad horizontal y copias de seguridad automáticas. El uso de un servicio gestionado asegura que la persistencia de la información sea independiente del servidor de cómputo y mantenga altos estándares de confiabilidad.

\subsection{Hostinger y AWS Certificate Manager (ACM)}

El sistema utiliza Hostinger \cite{hostinger_web} para la resolución de nombres de dominio y la gestión de registros DNS. Por otro lado, ACM (por abreviación, Amazon Certificate Manager) centraliza la provisión de certificados de seguridad para los servicios alojados en la nube. Ambas tecnologías trabajan de forma conjunta para asegurar que el acceso a la plataforma web y a la interfaz de programación de aplicaciones se realice bajo un entorno validado y seguro.
